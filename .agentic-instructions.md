# SixSeven: Agentic Debate Simulator - Complete Project Context

*Last Updated: February 14, 2026*

## Project Overview

**SixSeven** is an end-to-end agentic debate simulation system that orchestrates structured debates between LLM-based agents arguing opposing positions on conspiracy theories. The system uses a moderator agent to control debate flow, logs all interactions in a canonical format, and analyzes persuasion dynamics and language use patterns.

**Primary Output**: An automated debate system that runs on local infrastructure (Ollama) and cloud APIs (Google Gemini), producing reproducible, analyzable debate transcripts for research on persuasion and argumentation.

## Quick Start

### Installation
```bash

git clone <repo>
cd SixSeven
pip install -e .

pip install -r requirements.txt
```

### Single Debate

### When Adding Features

1. **Check DI Boundaries First** (`src/debate_sim/core/protocols.py`)
   - If the feature introduces a new I/O boundary, define a Protocol first
   - Wire the implementation through `container.py` — never import concrete classes in orchestrator

2. **Update Schemas** (`src/debate_sim/schemas.py`)
   - Ensure Pydantic models validate new fields
   - Maintain JSON serialization

2. **Modify Prompts Carefully** (`src/debate_sim/prompts/`)
   - Always end with: "Return ONLY valid JSON matching the schema. No extra text."
   - Test with actual models (Ollama first, then Gemini)
   - Keep word counts reasonable to avoid token overflow

3. **Update Analysis** (`src/debate_sim/analysis/`)
   - Add new metrics/features to `metrics.py` or `features.py`
   - Update `analysis_runner.py` to compute new fields
   - Generate visualizations if relevant

4. **Test Before Batch Runs**
   ```bash
   python cli/main.py  # Single debate
   python tests/validation/validate_run.py artifacts/run_*  # Validate output
   ```

5. **Version Control**
   - Keep prompt iterations in git
   - Document changes in commit messages
   - Tag release versions before batch runs

### Dependency Injection Architecture

**CRITICAL: All future integrations MUST respect the existing DI layer. New I/O boundaries (LLM providers, search backends, exporters, etc.) MUST be added as Protocol abstractions, not as hard-coded dependencies.**

#### Core DI Files
- **`core/protocols.py`**: Defines 6 `@runtime_checkable` Protocol ABCs:
  - `LLMClient` — raw LLM call interface
  - `StructuredLLMService` — structured (Pydantic) LLM output
  - `SearchProvider` — web search abstraction
  - `PromptLoader` — prompt file loading
  - `ArtifactExporter` — debate artifact writing
  - `DebateAnalyzer` — analysis pipeline interface
- **`core/container.py`**: `DebateServices` dataclass (aggregate root) + adapter classes + `build_default_services(config)` factory
- **`core/errors.py`**: Shared exception types (`LLMResponseError`)

#### DI Rules for New Features
1. **New LLM Provider** (e.g., Anthropic, OpenAI):
   - Implement `LLMClient` protocol (and/or `StructuredLLMService`)
   - Register in `build_default_services()` or add a new factory path
   - Do NOT import the new client directly in `orchestrator.py`

2. **New Search Backend** (e.g., Tavily, SerpAPI):
   - Implement `SearchProvider` protocol
   - Swap in `container.py` factory — zero changes to debate logic

3. **New Export Format** (e.g., Parquet, SQLite):
   - Implement `ArtifactExporter` protocol
   - Register in container — `writer.py` and orchestrator remain untouched

4. **New Analysis Module**:
   - Implement `DebateAnalyzer` protocol if it's a full pipeline replacement
   - Or extend existing `analysis_runner.py` if additive

5. **Batch Runner Variant**:
   - Inherit from `BaseBatchRunner` (`cli/base_batch.py`)
   - Override `_build_configs()` for model combinations
   - Shared DI wiring, resume logic, and artifact management come for free

#### Anti-Patterns to Avoid
- ❌ Importing concrete implementations directly in orchestrator or batch runners
- ❌ Adding `if provider == "x":` branches in debate logic
- ❌ Creating new I/O boundaries without a corresponding Protocol
- ❌ Bypassing `DebateServices` to pass individual dependencies

### Performance Notes
- **Single Debate**: ~2-5 minutes (Ollama), ~30 seconds (Gemini)
- **Full Batch**: Hours depending on model count and API limits
- **Search**: ~500ms per query (DuckDuckGo)
- **Analysis**: ~1 second per debate

## Common Tasks for Agentic Coding

### Adding a New Conspiracy Topic
1. Edit `src/debate_sim/topics.py`
2. Add entry to `CONSPIRACY_TOPICS` list
3. Run `python view_topics.py summary` to verify
4. Re-run batch experiments

### Changing Debate Parameters
1. Edit `config/config.ini` or set environment variables
2. Modify `DEBATE_ROUNDS`, `DEBATE_WORD_LIMIT`, etc.
3. Test single debate: `python cli/main.py`
4. Validate: `python tests/validation/validate_run.py`

### Iterating on Agent Prompts
1. Edit files in `src/debate_sim/prompts/`
2. Test with: `python cli/main.py` (runs single debate)
3. Check `artifacts/run_*/transcript.md` for readability
4. Validate JSON output: `python tests/validation/validate_run.py`

## Troubleshooting

### "Connection refused" for Ollama
- Ensure Ollama is running: `ollama serve`
- Check endpoint in config/config.ini: `http://localhost:11434/v1`

### Gemini API errors
- Verify API key in `config/config.ini`
- Check daily quota (1,500 requests/day)
- Rate limit: 15 requests/minute

### Schema validation errors
- Check Pydantic models in `schemas.py`
- Ensure LLM output matches expected JSON structure
- Verify prompt ends with JSON instruction

### Analysis won't run
- Check if metrics were computed: `memory.json` should have debate log
- Verify NLTK data is downloaded: `python -m nltk.downloader punkt wordnet`
- Check file permissions in `artifacts/`

### Memory overflow on batch runs
- Reduce `max_tokens` in config (default 900)
- Split batch into smaller runs
- Monitor system RAM during batch execution
